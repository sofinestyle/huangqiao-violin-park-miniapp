# 黄桥乐器文化产业园 Design System

版本：v0.1，2026年10月1日。状态：**设计规范提案，等待人工确认；尚未应用到代码**。适用微信原生游客端，后台业务界面不在本轮重构范围。

## 依据、确认状态与参考边界

**已确认 C**：企业品牌及服务定位；“东方乐器文化 × 手工制琴 × 现代产业园”；精致、温暖、克制、手工质感、文化感；暖米白、深胡桃木、少量香槟金和提琴琥珀棕；保留当前业务功能。用户指定 [homepage-target-v1.png](design-reference/homepage-target-v1.png) 为已确认首页优化视觉方向参考，本轮已实际查看。图片为865×1819像素，不是微信布局尺寸，不要求像素复制。

**原稿保留 R**：当前完整公司介绍、Hero两行标题及后台维护的点位、套餐和服务说明；内容与字段不因设计变更而改写。**补充建议 S**：本文精确色值、字号、间距、组件参数、状态表达及首页布局。它们是可实施提案，不声称从参考图精确采样，也不代表已批准。**待确认 D**：Phase 1实施授权、精确数值及布局、辅助英文、后续导航图标与素材选择，见[实施计划](UI_UX_REFACTOR_PLAN.md)。

参考图中值得提取的语言是大幅提琴摄影、暖色电影感、中文衬线、英文辅助、图片与留白、编号章节、图片融合的内容区及克制木色。参考图中的“提琴选购”、底部“提琴”、价格、5/27/8数量、金色大按钮、五列小入口及手写装饰均不能直接复制为正式功能或事实。本规范优先遵守用户最新文字要求：乐器范围、展示咨询、六个现有入口、禁止大面积金色及统一卡片模板。

## 1. Brand Personality｜品牌性格

| 特征 | 页面应体现 | 应避免 |
| --- | --- | --- |
| Premium / 精致 | 有明确主次、摄影细节、少而准确的装饰 | 金色堆砌、细字和低对比度冒充精致 |
| Warm / 温暖 | 米白底、木色、自然光与清楚服务入口 | 生硬公文页面、冷灰后台模板 |
| Craftsmanship / 手工质感 | 木纹、制琴动作、工具与材料实拍 | 假纹理覆盖文字、虚构工艺或认证 |
| Editorial / 编排感 | 大图、编号章节、留白和不同内容结构 | 每一块都是同尺寸描边圆角卡片 |
| Cultural / 文化感 | 中文衬线标题、产业及乐器故事 | 政府官方平台表述、旅游景点模板 |
| Brand & Service / 品牌及服务 | 展示、咨询、研学、教学、参观的清楚入口 | 商城促销、价格刺激、购物车 |

“Violin”用于品牌视觉锚点，不能把已确认的五类乐器业务缩回提琴。YorRay标志使用现有原件，左侧标志、右侧园区名称；公司全称在关于我们及完整介绍保留。

## 2. Color System｜色彩系统

以下为S提案，Token名字用于规范；本轮没有创建WXSS变量或修改任何颜色。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `color-bg` / Warm Ivory | `#F7F3E9` | 主背景、页面留白，延续当前米白基础 |
| `color-surface` | `#FFFDF7` | 少量功能面板、状态容器；不是每个模块的底色 |
| `color-walnut` / Deep Walnut | `#3C2B24` | 品牌主色、标题、主按钮、少量深色内容区 |
| `color-text` | `#3C2C20` | 正文、操作及关键信息 |
| `color-text-secondary` | `#6C5948` | 摘要、说明、辅助文字，兼顾可读性 |
| `color-gold` / Champagne Gold | `#B99A68` | 小线条、编号装饰、局部标记；不用于米白底上的小正文 |
| `color-gold-text` | `#80613B` | 需要金色语气且必须可读的文字，仍少量使用 |
| `color-amber` / Violin Amber | `#965A32` | 少量强调与工艺相关信息，不替代主色 |
| `color-line` | `#E5DCCB` | 非关键分隔线、淡结构线；不能独自表示选中或错误 |
| `color-success` / `color-error` / `color-info` | `#42644D` / `#A13E35` / `#456270` | 状态配文字/图标；不是新业务状态或自动确认规则 |

香槟金只作强调，不做整页背景、大块渐变或大面积金色按钮。照片本身的琥珀、木棕可占较大视觉面积，界面装饰不随之增加。Hero必要的暗色遮罩用于文字可读性，不作为全站渐变风格。

**对比度目标**：普通有效信息文本至少4.5∶1；满足大字条件的文本至少3∶1。项目建议正文仍采用4.5∶1以上组合，关键控件边界与状态标识亦需可辨。这是参照[W3C文本对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)的设计标准，不是已经完成的全端无障碍认证。

| 不透明前景 / 背景 | 本轮计算结果 | 设计用途 |
| --- | --- | --- |
| Walnut / Ivory | 12.124∶1 | 标题与主色信息 |
| Secondary / Ivory | 5.997∶1 | 普通辅助正文 |
| Surface / Walnut | 13.207∶1 | 主按钮文字 |
| Gold text / Ivory | 5.135∶1 | 少量文字强调 |
| Amber / Ivory | 4.980∶1 | 辅助文字强调 |
| Gold / Ivory | 2.404∶1 | 仅非关键信息装饰，不能作正文或唯一控件提示 |

结果按sRGB相对亮度公式计算，显示值作小数展示，达标判断不四舍五入；[计算数据](design/ui-audit-2026-10-01/contrast.json)可核查。摄影背景需逐图检查遮罩后最弱区域，不能用上述纯色比值替代。

## 3. Typography｜字体组合

中文品牌与章节标题优先系统衬线 `"Songti SC", STSong, "Noto Serif CJK SC", serif`；正文与操作使用 `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`。这些是回退顺序，不保证各系统均具备相同字体。Android缺少衬线时保留清楚层级，不为“像图”强行下载未知字体。

英文辅助建议采用系统衬线或正文系统字体，短而有语义；中文主信息始终先读到。可讨论 `EXPLORE THE PARK`、`RECOMMENDED` 等章节辅助标识，待确认后才使用；不照搬图中英文口号、手写签名或新增未经审核品牌文案。字体若未来引入自有文件，先核实授权、体积和加载方式，另列范围，不依赖远程字体才能显示业务信息。

## 4—6. Font Size / Font Weight / Line Height｜字号、字重与行高

以750rpx设计参考宽度描述建议，375px逻辑宽设备上的示例约为rpx的一半；实际以原生设备测量为准。

| 文本角色 | 建议字号 | 字重 | 行高 | 使用约束 |
| --- | --- | --- | --- | --- |
| Hero中文标题 | 52—60rpx | 600 | 1.25—1.35 | 两行现有标题，避免溢出；长内容可增高容器 |
| 园区品牌名称 | 30—34rpx | 600 | 1.35 | 允许合理换行，不能与原生胶囊重叠 |
| 章节标题 | 38—42rpx | 600 | 1.35 | 中文衬线，层级清晰 |
| 内容标题 | 30—34rpx | 500—600 | 1.45 | 长点位/套餐名可多行完整显示 |
| 正文/介绍 | 30rpx | 400 | 1.7—1.85 | 完整介绍保留，避免过小密字 |
| 按钮/入口 | 28—30rpx | 500—600 | 1.4—1.5 | 避免截断关键动作 |
| 辅助信息 | 26rpx | 400 | 1.6 | 仍需足够对比度 |
| 英文短标识/非关键说明 | 24rpx | 400—500 | 1.5 | 不承载唯一操作或必读业务规则 |
| 装饰编号 | 64—80rpx | 400 | 1.0—1.2 | 不与标题抢主次，不能代替标题 |

不使用极细字重，不把所有标题加粗，不用固定高度裁掉文字。系统字体放大及长中文名称是后续真机验证项；本轮未证明字体缩放已适配。不能为装饰缩小咨询、预约及规则说明。

## 7. Spacing System｜留白与间距

基础步长8rpx；建议序列8/16/24/32/40/48/64/80rpx。横向页面留白32rpx，窄屏按实际调整；同组文字8—16rpx，标题与正文16—24rpx，模块内部24—32rpx，章节间48—64rpx。大图可横向通栏，文字仍有安全边距。不能用大量空白把教学、咨询或研学入口推到难以发现的位置。

首页让摄影、短标题和服务动作先建立层级，完整公司介绍可移到品牌故事区，但不删减、不折叠成不可见内容、不新增展开业务。不把参考图做成长宽固定的海报嵌入小程序。

## 8. Border Radius｜圆角

建议0/8/16/24rpx四级：文字区和章节分区可无圆角；小图片或功能控件8—16；少量图片融合推荐区16—24。胶囊只用于少量短标签或既有筛选控件。全站不能统一套24rpx白色矩形，不能用大圆角减小表单或点击面积。参考图中大量圆角卡片仅部分借鉴，服从用户禁止模板化的要求。

## 9. Shadow｜阴影

默认无阴影，以背景、摄影和间距区分层次。仅真实浮层/抬起层可建议 `0 6rpx 20rpx rgba(60,43,36,0.08)`，并验证WXSS支持及低端机表现。首页常规区块不叠加阴影；不使用发光、内阴影或多层拟物效果。系统弹窗沿用原生层级。

## 10. Button｜按钮与点击区域

主按钮：深胡桃木底、暖白字、16rpx圆角、左右24—32rpx内边距；次按钮：透明/米白底、深色字及必要边界；文字入口：深色文字+细箭头或下划线等提示，真实可点击区域扩大，不能只让箭头可点。香槟金用于小标记，Hero CTA亦优先深色/暖白组合，不照搬大金色药丸。

项目操作舒适度目标为**至少44×44px逻辑点击区域**，在常用375px宽度可用88rpx高度，同时设置44px下限以保护窄屏；相邻目标建议至少8px间距。它是项目建议，不能把它写成WCAG 2.5.8的强制44px标准。该标准的最低目标为24×24 CSS px并有例外，详见[W3C目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。原生小程序需按实际逻辑尺寸测量。

有效、按下、禁用、加载均有可辨状态。按下可深色变化/轻微透明度反馈，保留原有事件；加载保留现有请求及防重复逻辑，不能在视觉阶段增加提交路径。不可报名、待确认等状态同时使用原业务文字，颜色不能改变含义。

## 11. Card｜卡片与内容容器

采用不同内容结构，而非统一卡片模板：品牌故事为开放式正文；园区探索为摄影与标题融合的大区和紧凑点位条目；推荐用图片主导、开放文字说明和清楚整块点击提示；业务表单/状态确需边界时才用功能面板。产品目录保留现有列表信息和1∶1封面，后续另阶段改善。

一张推荐卡保留现有套餐名、时长及详情跳转，不加入参考图价格、促销标签或假评分。不把装饰图标当业务按钮，不裁切不可替代的信息。图片、标题和箭头指向同一目标，避免嵌套冲突点击。

## 12. Image Ratio｜摄影、比例与素材

| 场景 | 建议/约束 | 内容与裁切 |
| --- | --- | --- |
| 首页Hero | S：约4∶3框架，必要时随文字增高 | 琴体/工艺主角清楚，左侧或下方文字安全区；不是固定海报高度 |
| 园区主视觉 | S：约16∶9至3∶2 | 建筑与产业场景对应实际点位，文字避开高亮复杂区域 |
| 推荐套餐 | S：优先16∶9；窄屏完整纵向呈现 | 人物/手工主体不被裁掉，不机械套用参考图双列小字 |
| 乐器、文创列表 | **C：1∶1** | 容器等比裁切显示，原图和后台文件不变 |
| 现有详情图库、视频 | R：沿用当前比例及播放方式 | 本阶段不统一改比例或播放器 |
| YorRay标志 | C：保持原件宽高比、aspectFit | 深木色承托白色标志，不重新绘制 |

Phase 1沿用 `site.images[1]`、`spots[].cover`、`packages[].cover` 数据来源，不新增字段或替换后台记录。参考图整张图片只在文档中展示，不能作为页面背景或分割成业务按钮。原图不覆盖、不裁切保存；新摄影、AI生成或资源压缩有真实需要时另列素材任务，先核实用途和授权，不默认花费。

## 13. Icon System｜图标

优先克制的单色线性图标，建议2px视觉线宽、20—24px视觉尺寸；点击区域仍遵守按钮标准。箭头、定位、播放等图形需配中文名称，不用仅金色区分状态。避免彩色三维、Emoji、手写装饰混用和每个栏目一套图库。

本轮不安装图标库、不创建图标。首页Phase 1可用简单显示箭头增强已有入口提示，不能增加业务事件。底部导航图标与图标资源需后续单独确认，保留当前原生文本tabBar。

## 14. Navigation｜导航

底部导航固定**首页、乐器、文创、研学、我的**，顺序、页面路径和跳转方式冻结。教学由首页进入；六个已有快捷入口必须全部保留。参考图中“提琴”需按当前“乐器”理解，“选购”不能引出在线购买。

保留当前原生顶栏、胶囊和系统返回。本阶段不改 `app.json`、不建立自定义tabBar或自定义顶栏；页面品牌条优化只在既有内容区域完成。双园区名称的占高属于现状可改善点，但合并原生顶栏属于后续范围，不能为了复制参考图提前实施。

## 15. Section Layout｜首页章节组织

建议结构：原生顶栏及品牌条 → 提琴工艺Hero与既有导览动作 → 六个服务入口的分组编排 → 保留完整介绍的品牌故事 → 园区探索（四个现有点位） → 两个现有推荐套餐 → 原公告/服务说明与关于我们。全部使用当前字段、循环与事件。

六入口可分为“乐器与文创”“研学与教学”“导览与咨询”的三个视觉组；保留六项可见且可直达，避免五列挤压和平均功能宫格。探索区可让一个既有点位视觉更突出，其余条目紧凑呈现，但不减少四条、不改数据排序逻辑、不伪造全景。编号01/02用于区分章节，可有少量英文辅助；品牌故事与服务操作不能混为大量描边面板。

## 16. Interaction State｜交互状态

| 状态 | 显示规则 | 冻结要求 |
| --- | --- | --- |
| 默认/按下 | 清楚动作提示，按下后有轻量反馈 | 沿用既有事件和目标 |
| 选中 | 文字+底色/线条共同表示 | 五导航及现有筛选逻辑不变 |
| 禁用/不可报名 | 对比清楚且说明原因 | 不改变满员、暂停或人工确认规则 |
| 处理中 | 保留操作名称与现有加载状态 | 不新增API、定时轮询或重复提交 |
| 成功/待确认 | 按已有状态文字展示 | 提交成功不改为确认成功或占名额 |
| 失败/重试 | 原错误信息、清楚可触达重试 | 不吞错误、不通过装饰伪造成功 |

WXSS的 `hover-class` 等视觉反馈如使用，必须在原生渲染中确认；不能用复杂动画代替即时反馈。辅助阅读标签可在批准后评估原生支持，不凭静态文档宣称屏幕阅读器已经通过。

## 17. Loading / Empty / Error State｜页面状态

- **Loading**：沿用当前 `loading` 状态与共享模板，Phase 1可在首页作用域调整排版；预留稳定空间，文字清楚。骨架只有现有状态足够支持时才讨论，不能新增请求或改加载时序。
- **Empty**：保持 `site`、`packages.length` 等现有条件与数据绑定。内容少时保留已有入口；不填造统计、套餐或产品。若新的空态展示需要新增状态判断，先列范围/CR，不在纯样式任务中擅改分支。
- **Error**：保留原 `error` 与重试回调，使用错误文字和足够大按钮，禁止浅金字或无按钮错误画面。
- **图片失败**：在设计中预留暖灰/米白底及合适比例；当前首页没有独立图片失败处理，本轮未新增。若需要失败事件、状态字段或新组件，另提技术范围及CR，不能假称已有兜底。

状态设计与实现事实分开：本轮只捕获正常首页，未制造错误或清空数据验证；这些规范是后续验收目标。

## 18. Motion｜动效原则

建议120—180ms按下反馈，必要的过渡160—220ms，以透明度或轻微颜色变化为主。不做Hero自动轮播、视差、首屏全屏入场、自动播放音乐/视频、抖动促销或持续金光。参考图轮播点不代表已批准新增轮播。低端机、减少动态效果偏好和系统辅助功能需后续验证；禁用动画也必须能使用全部功能。

## 19. 微信小程序适配原则

继续原生 TypeScript + WXML + WXSS，保留现有组件框架和编译配置，不迁移到React/Taro/uni-app，不从工具开关推断已采用Skyline。使用页面作用域样式，Phase 1若建立Token文件只从首页引用，不修改全局 `app.wxss` 影响18个页面。

布局以rpx为设计参考，实际点击最小尺寸结合px下限；不固定430px或参考图像素宽度。尊重原生顶栏、胶囊、返回、底部tabBar和安全区，不能画假的胶囊/状态栏。使用 `<image>` 与 `aspectFill/aspectFit`，不把整张视觉参考图嵌入交互界面。
