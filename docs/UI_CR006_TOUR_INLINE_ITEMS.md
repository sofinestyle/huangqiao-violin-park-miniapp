## 申请的最小冻结例外

现有点位模型没有独立标签、游玩项目及预计时长；后台也没有编辑入口。直接按点位id硬编码会导致后台维护失效，故申请两项**可选、仅spot使用**的展示字段：

| 字段 | 格式及校验 | 用途 |
| --- | --- | --- |
| `tags` | 字符串数组；最多12项，每项1—40字；缺省为空 | 介绍下方点位标签 |
| `visitItems` | 数组，最多20项；每项`{name,description,durationNote}`，名称1—80字、说明0—200字、预计时长说明1—40字 | 项目名称及说明在左，预计时长在右；时长为展示文字，不参与任何预约、容量、收费或接待计算 |

旧记录不要求补齐，不做数据库表结构迁移。服务端沿用现有content JSON持久化、权限、版本冲突及审计，新增字段仅对spot接收和校验，其他内容类型不接收。后台仅在现有点位编辑抽屉增加标签及项目增删/输入，不改变后台整体UI、账号、发布流程或其他内容类型。游客页只读取已发布的资料；不按id补写静态业务内容，不使用其他业务字段模拟项目表。

扩展文件白名单：`server/service.mjs`（仅点位字段接收/校验）、`admin/src/Content.jsx`（仅点位字段编辑）、一份隔离服务端回归测试、tour WXML（新增动态标签/项目显示）。不改公共TS、API路径、身份、预约、数据库结构、首页、共享导航及其他页面。
