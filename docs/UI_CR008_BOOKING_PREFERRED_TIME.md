# UI-CR008：游客预约品牌栏与自由填写意向时段

2026年10月2日；状态C，用户直接四项修改指令已授权必要实施。基线3143570。用户要求：顶部增加品牌栏并改名“游客预约申请”；移除“个人/家庭预约申请”；意向时间段自行输入；移除独立资料说明按钮。

## 必要修改范围

booking WXML/WXSS/JSON/TS增加品牌栏、同步原生标题，普通申请删除重复正文标题；团体与跟团仍保留各自业务上下文标题。普通/团体的场次选择替换为最长100字的可选preferredTime文本，示例“上午9:00—11:00”；日期与套餐保持原选择方式。已成团活动继续显示其已发布日期和固定时段，不能自行更改。

自由时段需要独立保存，不能只改输入外观。server/service.mjs校验可选文本并保存在原request JSON中，不新增数据库表/列；后台Operations预约详情及游客record页面按字段存在显示。现有slotId接口兼容旧申请和跟团，不把自由文字解释为场次ID、容量或已确认安排。跟团请求携带非空preferredTime会被拒绝，防止固定活动被改为自由时段。

独立“查看资料使用与服务说明”按钮删除，原privacy事件移到同意文案里的“隐私与服务说明”链接；不自动同意，原consent服务端校验保留。

## 保护与验证

不改首页、公共导航、全局样式、数据库结构、场次与确认事务、费用、登录权限及历史记录。正式确认仍由工作人员选择合法场次并确认，原容量约束保持。前端不再依赖普通场次列表来填写意向，不影响已发布跟团详情读取。

新增隔离HTTP持久化/读取/幂等测试、可选字段兼容及格式/长度拒绝测试，既有跟团篡改测试增加自由时段拒绝场景。实际验证及未执行项见design/ui-booking-2026-10-02/ACCEPTANCE.md。不推送、部署或发布。
