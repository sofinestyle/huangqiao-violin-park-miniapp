# SQLite → PostgreSQL 审计

基线、日期和只读边界见[01](01-CURRENT_ARCHITECTURE.md)。结论：业务关系适合PG；现有SQL及同步调用不能原样运行。下列均为待实施设计，不是已执行Migration。

## 1. 表级映射与关系

实际13张应用表，另有SQLite内部sqlite_sequence。完整逐字段DDL/默认值/索引见本文件附录（直接读取实际Schema）；除DDL所列外，无额外DB CHECK、FK或唯一约束。state/type/roles的大部分合法性由Service校验，不应误写成数据库已约束。

| 表 | 主键/关联 | JSON字段 | 时间字段 | PG调整（其余普通TEXT/INTEGER可对应） |
| --- | --- | --- | --- | --- |
| content | id；kind下含site/product/package/lesson/spot；无FK；Product Code在data.code且无全局唯一 | data（含options/images/variantMode/version标记） | created_at/updated_at | data→JSONB，时间→timestamptz；id保留TEXT以兼容site等约定 |
| product_skus | id；product_id→content.id；全局Code唯一；产品+组合唯一 | option_values/images | created_at/updated_at | Code表达式唯一、JSONB CHECK、BOOLEAN、NUMERIC；详下 |
| accounts | id；username唯一；角色由Service检查 | roles | created_at | roles→JSONB数组；can_export/active→BOOLEAN |
| visitors | id；wechat_openid可NULL且唯一 | 无 | created_at | 常规TEXT/唯一可对应；时间转换；openid只在当前AppID作用域，环境隔离 |
| sessions | token_hash；owner按type关联账号或游客，实际无FK | 无 | expires_at为Unix毫秒INTEGER | 保留毫秒协议改BIGINT；owner多态不强行FK到一张表 |
| slots | id；package_ids/enrollment关联content，无DB FK | package_ids/enrollment | date/start/end为当地预约日/时 | JSONB；paused→BOOLEAN；date→DATE，start/end→TIME，API仍YYYY-MM-DD/HH:mm；capacity/external_count CHECK保留 |
| bookings | id；owner→visitors；slot_id→slots；assignee→accounts | snapshot/request/confirmed/contact_log | arrived_at/created_at/updated_at | snapshot/request→JSONB用于引用查找；confirmed/contact_log→JSON；时间→timestamptz |
| changes | id；booking_id→bookings；每预约唯一pending（部分索引） | data/result | created_at/handled_at | JSON；部分唯一索引PG支持；时间转换 |
| consultations | id；owner→visitors；assignee→accounts；产品/SKU关系在快照，无FK | snapshot/request/followups | created_at/updated_at | snapshot→JSONB；request/followups→JSON；时间转换 |
| idempotency | owner+route+key复合PK；owner逻辑关联，无FK | response | 无 | response→JSON；fingerprint保持TEXT原请求摘要，不从JSONB重新序列化生成 |
| media | id；content/SKU引用URL或mediaId，实际无FK | 无，rights是普通文字 | created_at | size→BIGINT；duration→DOUBLE PRECISION；时间转换；对象key映射见04 |
| audit | 自增整数id；actor/object多态，不设删除级联 | detail | created_at | id→BIGINT GENERATED BY DEFAULT AS IDENTITY；detail→JSON；三索引保留 |
| migrations | version整数PK | 无 | applied_at | PG单独初始迁移账本；时间→timestamptz，不伪装跑过SQLite1—5 |

除SKU ID可采用UUID列（已严格UUIDv4）外，其他ID先保持TEXT。HQ-/ZX-业务编号、site、system等不应机械改UUID。SKU product_id仍与content TEXT匹配。所有正式PK显式NOT NULL，消除SQLite普通TEXT PRIMARY KEY未写NOT NULL的宽松行为。

实际FK全部未声明ON DELETE CASCADE。当前产品安全删除由Service先删SKU再删content；PG建议保留显式同事务删除和FK NO ACTION，禁止级联咨询、预约、媒体、审计。

## 2. SQLite特性映射

| 当前特性 | PostgreSQL建议 | 风险/验证 |
| --- | --- | --- |
| prepare(sql).get/all/run + ? | await client.query(sql,[...]) + $1…；封装one/many/execute | 每层await、rowCount、空结果统一；不能仅字符串替换 |
| INTEGER布尔/+true/active=1 | BOOLEAN/true/WHERE active | API继续布尔；不接受字符串'false'当truthy |
| REAL参考价 | 无固定scale的NUMERIC，保持0..10000000且有限 | 当前没有只准两位小数的业务规则，不擅自NUMERIC(12,2)舍入；pg返回字符串，边界显式转有限number，null与0区分 |
| TEXT日期时间 | 时间戳timestamptz；预约DATE/TIME | UTC输出ISO；预约以Asia/Shanghai判日，避免Node时区改变日期；原applied_at混用SQLite时间格式不带入新库 |
| INTEGER毫秒/文件大小 | BIGINT | pg可能返回字符串，安全数范围校验后适配；COUNT/SUM及audit id也需契约一致 |
| AUTOINCREMENT | identity列 | 不迁移sqlite_sequence；序列允许空洞，不依赖连续编号 |
| INSERT OR IGNORE | INSERT … ON CONFLICT(明确目标) DO NOTHING | 不吞其他约束错误；Seed与Migration区别处理 |
| datetime('now') | CURRENT_TIMESTAMP或既有ISO参数 | DB时区与API序列化统一 |
| json_extract(x,'$.id') | x->>'id'；嵌套x#>>'{enrollment,id}' | NULL/缺失/JSON null需用fixture验证 |
| json_each(package_ids) | jsonb_array_elements_text或JSONB包含查询 | 参数绑定；索引由EXPLAIN依据决定 |
| slot_id IN related_slots | slot_id IN (SELECT id FROM related_slots) | SQLite简写不可照搬 |
| json_valid/json_type | JSON(B)入库解析 + jsonb_typeof CHECK | object/array仍显式限制 |
| typeof整数检查/GLOB | 原生整数列 + 正则CHECK | 不移除边界检查；非法NaN/Infinity前后端均拒绝 |
| COLLATE NOCASE | unique(lower(sku_code COLLATE "C")) | ASCII Code规则不变，展示保留大小写 |
| 部分唯一索引 | 原样结构迁移 WHERE state='pending' | 不误改为所有changes均唯一 |
| PRAGMA FK/WAL/busy_timeout/quick_check | FK默认强制；MVCC；lock/statement timeout；恢复核对 | 没有逐条等价PRAGMA；应用不配置PG WAL |
| BEGIN IMMEDIATE | BEGIN +业务行锁+COMMIT/ROLLBACK | BEGIN本身不能提供SQLite全库写串行保障 |
| sqlite_master/VACUUM INTO | PG目录信息/pg_dump与受控恢复 | 本地SQLite备份仍归档；不能拿它当PG恢复 |

JSON选择依据：[PostgreSQL JSON类型](https://www.postgresql.org/docs/current/datatype-json.html)。JSONB适合真实路径查询；JSON保留无查询需求的序列化载荷，二者都验证JSON语法。options仍在content.data内，不新建全局字典。snapshot选JSONB是为现有删除引用检查，历史不可变由应用禁止更新保证，不依赖JSON保留键顺序。普通rights、name、fingerprint等继续TEXT。

pg自动解码JSON/JSONB；当前decode/JSON.parse必须移除或集中适配，不能二次parse。出入站数字与DATE/TIME单独归一化。[node-postgres类型](https://node-postgres.com/features/types)。

## 3. SKU约束方案

建议PG迁移内定义（示意未执行）：

```sql
CHECK (sku_code = btrim(sku_code) AND sku_code COLLATE "C" ~ '^[A-Za-z0-9_-]{1,64}$');
CREATE UNIQUE INDEX product_skus_code_ci ON app.product_skus (lower(sku_code COLLATE "C"));
UNIQUE (product_id, combination_key);
CHECK (jsonb_typeof(option_values) = 'object');
CHECK (jsonb_typeof(images) = 'array');
CHECK (reference_price IS NULL OR (reference_price >= 0 AND reference_price <= 10000000));
CHECK (sort_order BETWEEN 0 AND 10000);
CHECK (disable_reason IN ('','manual','structure'));
```

Code冲突查询也用lower + C collation；依赖DB唯一保护竞态，23505按约束名映射SKU_CODE_CONFLICT/组合冲突，不只预查。无需citext扩展。[表达式唯一索引](https://www.postgresql.org/docs/current/indexes-expressional.html)。

combination_key继续服务端依据稳定Option/Value ID规范化，与Label及顺序无关；唯一约束包含停用历史，不能增加WHERE enabled导致重复身份。simple固定内部key不变。Option/Value.enabled、SKU.enabled/disable_reason语义不变；恢复保留ID/Code/参考价/图片和manual原因。最多3维、20启用值/维、50候选组合继续Service校验，JSON CHECK不能代替组合与归属校验。Product Code无唯一约束属于既有风险，本次迁移不扩大重构。

## 5. 事务与并发（最大风险）

推荐普通业务事务READ COMMITTED，明确同一client、行锁和一致锁顺序。每个事务从pool借一个client，全链路下传到Service/helpers/audit，所有await完成后COMMIT；异常ROLLBACK，finally release。禁止事务中夹用pool.query或同步fn包装异步回调导致提前提交。[pg事务](https://node-postgres.com/features/transactions)。

| 场景 | 当前保护 | PG建议 |
| --- | --- | --- |
| 预约确认/改期/取消、容量/外部人数调整 | BEGIN IMMEDIATE把所有写串行；SUM确认/完成/未到访人数+external_count | 统一锁slots目标行FOR UPDATE，再SUM、检查、写booking/change/audit；跨场次按id顺序锁旧/新slots；所有影响容量入口同协议 |
| 申请/确认状态、版本 | 同步读版本再UPDATE | 锁booking行再读version；或条件UPDATE id+version RETURNING判0行409；关联changes同事务，pending唯一继续DB兜底 |
| Content+SKU保存 | 一个同步事务+version+全部校验 | 锁content行，再读取当前Options/SKU、校验version、执行diff和audit；新建站点singleton另用固定事务锁防并发双site |
| 安全删除Content | 全库写锁覆盖检查/删SKU/删content/audit | 锁content FOR UPDATE后重查状态/version/所有引用；引用创建方也须锁同content FOR SHARE并重查可用性；单独锁被删行无法阻止JSON引用新增 |
| 咨询创建/快照 | 外层idempotent事务内读取Product/SKU | content FOR SHARE与SKU更新用的content FOR UPDATE互斥；同事务重新判发布/current/enabled、保存快照和幂等结果 |
| 研学引用写入 | package_ids、snapshot/request中JSON引用 | createBooking/saveSlot包括旧新套餐都按ID顺序锁content；删除检查与新增场次/预约互斥，不能依赖没有FK的JSON |
| 幂等首次竞争 | 先查→执行→插入，SQLite写锁串行 | 对owner/route/key使用事务级advisory lock后查指纹/执行/写响应，仍保留复合PK；哈希冲突仅额外串行、不替代真实key比较；不插空response提前提交 |
| 最后一个管理员 | 全库写锁内扫描其他active admin | 所有账号创建/角色/启停使用同一固定事务advisory lock，再锁目标账号；防两个不同管理员同时互相停用造成0管理员 |
| 登录及账号/audit | 更新账号已有事务；创建账号/登录写session+audit没有统一事务 | 创建账号+审计、登录session+审计改原子；微信openid唯一upsert避免异步并发首次登录冲突；微信网络请求在DB事务外 |
| 审计分页 | COUNT和SELECT两个同步语句 | 只读REPEATABLE READ事务获取同快照total/items；保留created_at DESC,id DESC；不改分页协议 |
| 上传media/audit | 先文件再分别INSERT和audit | metadata+audit同PG事务，文件对象独立补偿，不能假设跨云存储ACID |

预约SUM结果本身不能直接用FOR UPDATE保护；锁的是公共slots行。所有增加/释放名额的路径必须遵守，否则READ COMMITTED会超额。REPEATABLE READ不能代替写锁；SERIALIZABLE可作备选，但要求处理40001，不能把失败重试变成重复业务。

统一锁顺序建议：幂等/策略事务锁 → content ID升序 → slots ID升序 → booking/consultation → changes →写audit；操作时若发现锁前读到的关系已变，回滚重取，不倒序补锁。账号策略不在业务事务末尾再获取。死锁40P01/序列化40001限定次数重试整事务，同幂等键；非幂等写不得在提交结果不明时盲重放。网络调用/对象传输放事务外。须用两条独立PG连接/两个Server实例验证，单进程同步测试不能证明此设计。

## 6. 访问层与异步范围

推荐标准node-postgres/pg，保持Node Service承担业务。CloudBase SDK适合平台存储/管理接口，不把每条业务SQL改PostgREST链式请求，更不把整套Service搬入RPC函数。官方[PG FAQ](https://docs.cloudbase.net/en/database/postgresql/faq)说明SDK不直接提供事务操作；[连接指南](https://docs.cloudbase.net/database/postgresql/connecting-to-postgresql)支持服务端协议直连。

| 层 | 影响 | 内容 |
| --- | --- | --- |
| Database/Transaction | High | 新连接池、PG Schema、tx client、SQL及类型 |
| Service/helpers/security | High | 同步调用链全量await；禁止async filter/map误用；锁/错误码 |
| HTTP | High | handler虽async但service/db现在同步；必须逐路由等待/捕获、关闭连接池 |
| Tests/fixture | High | assert.throws改rejects、异步setup/teardown、PG真实并发/故障回滚 |
| Admin/Mini数据契约 | Low至Medium | 原API尽量不变；JSON/数字/时间严格回归，部署配置另见03/05 |
| shared纯SKU算法 | Low | 无数据库部分保留，稳定ID规则不重写 |

## 7. PG Migration和连接池

采用A：新PG初始迁移（如pg/001_initial），吸收SQLite最终13表结构及4/5索引约束，不翻译旧测试文案Migration2，不导入SQLite数据。保留旧文件历史，PG用独立带版本/校验和/执行时间账本；迁移任务单实例执行并锁定，业务实例不自动DDL。

CloudBase PG的DDL授权路径与普通自建PG不同：官方[权限说明](https://docs.cloudbase.net/authentication-v2/auth/auth-pg)指出cloudbase_postgres角色DDL受限制，CREATE TABLE等需ExecutePGSql高权限路径。实施前在获批staging验证整份初始Schema、schema/GRANT、迁移锁、失败回滚能否受控执行；若云API多调用无法共享事务，使用可审查的单次事务执行单元并验证失败无半迁移，不能假称普通pg连接可任意建表。业务运行时用最小DML账号，不持有迁移密钥。app schema是否可创建/隔离也须此时验证，失败则使用public下受控前缀和禁用直接客户端权限，不擅改业务架构。

连接池按 `最大实例数 × 每进程pool.max + 发布重叠实例 + 平台/迁移/备份预留 < 可用DB连接预算` 规划；每进程一个pool，闲置连接回收、连接获取/查询/锁/事务闲置超时分别设置。SIGTERM先停止接单、有限等待在途请求、归还client并pool.end；监控wait队列/泄漏。参数由云端限额与staging负载确定，不把示例5或默认10写成生产值。[连接池原则](https://node-postgres.com/guides/pool-sizing)。

CREATE TABLE consultations (id TEXT PRIMARY KEY, owner TEXT NOT NULL REFERENCES visitors(id),
      snapshot TEXT NOT NULL, request TEXT NOT NULL, state TEXT NOT NULL, assignee TEXT REFERENCES accounts(id),
      followups TEXT NOT NULL DEFAULT '[]', public_note TEXT NOT NULL DEFAULT '', version INTEGER NOT NULL DEFAULT 1,
      created_at TEXT NOT NULL, updated_at TEXT NOT NULL);

```sql
CREATE INDEX consultations_owner ON consultations(owner);
```

### product_skus

```sql
CREATE TABLE product_skus (
    id TEXT PRIMARY KEY NOT NULL,
    product_id TEXT NOT NULL REFERENCES content(id),
    sku_code TEXT NOT NULL COLLATE NOCASE UNIQUE CHECK(length(sku_code) BETWEEN 1 AND 64 AND sku_code=trim(sku_code) AND sku_code NOT GLOB '*[^A-Za-z0-9_-]*'),
    option_values TEXT NOT NULL CHECK(json_valid(option_values) AND json_type(option_values)='object'),
    combination_key TEXT NOT NULL,
    reference_price REAL CHECK(reference_price IS NULL OR (typeof(reference_price) IN ('integer','real') AND reference_price>=0 AND reference_price<=10000000)),
    images TEXT NOT NULL DEFAULT '[]' CHECK(json_valid(images) AND json_type(images)='array'),
    enabled INTEGER NOT NULL CHECK(enabled IN (0,1)),
    sort_order INTEGER NOT NULL CHECK(typeof(sort_order)='integer' AND sort_order BETWEEN 0 AND 10000),
    disable_reason TEXT NOT NULL DEFAULT '' CHECK(disable_reason IN ('','manual','structure')),
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
    UNIQUE(product_id,combination_key));
```

```sql
CREATE INDEX product_skus_product_id ON product_skus(product_id);
```

- 自动索引 `sqlite_autoindex_product_skus_1`：id。
- 自动索引 `sqlite_autoindex_product_skus_2`：sku_code。
- 自动索引 `sqlite_autoindex_product_skus_3`：product_id, combination_key。

### sqlite_sequence

```sql
CREATE TABLE sqlite_sequence(name,seq);
```

SQLite内部自增序列状态表；name/seq无显式类型、主键或索引。仅为audit的AUTOINCREMENT维护状态，不作为PG业务表迁移。
