## huangqiao_app 最小权限清单（未在云端执行）

按当前正常 Server SQL 的表级权限汇总；不是迁移、恢复、测试 Seed 或运维账号权限。角色须具备 LOGIN，且不能通过角色继承间接获得更高权限。

| 对象 | 权限 |
|---|---|
| DATABASE postgres-i56vqlwu | CONNECT |
| SCHEMA app | USAGE |
| content、product_skus | SELECT、INSERT、UPDATE、DELETE |
| accounts、visitors、slots、bookings、changes、consultations | SELECT、INSERT、UPDATE |
| sessions | SELECT、INSERT、DELETE |
| idempotency、media、audit | SELECT、INSERT |
| migrations | SELECT |

供后续授权审查的清单 SQL（本轮未执行）：

```sql
GRANT CONNECT ON DATABASE "postgres-i56vqlwu" TO huangqiao_app;
GRANT USAGE ON SCHEMA app TO huangqiao_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON app.content, app.product_skus TO huangqiao_app;
GRANT SELECT, INSERT, UPDATE ON app.accounts, app.visitors, app.slots,
  app.bookings, app.changes, app.consultations TO huangqiao_app;
GRANT SELECT, INSERT, DELETE ON app.sessions TO huangqiao_app;
GRANT SELECT, INSERT ON app.idempotency, app.media, app.audit TO huangqiao_app;
GRANT SELECT ON app.migrations TO huangqiao_app;
```

不授予 SUPERUSER、CREATEDB、CREATEROLE、BYPASSRLS、对象所有权、schema/database CREATE、TRUNCATE、GRANT OPTION 或 migrations 写权限。需另行核查已有 PUBLIC/角色继承授权，追加 GRANT 不会撤销原有高权限；本轮不修改云端 ACL。

当前 audit 使用 GENERATED BY DEFAULT AS IDENTITY，业务 INSERT 省略 id，未显式调用 nextval/currval/setval，因此无需额外授予该内部序列权限，更不授予 ALL ON ALL SEQUENCES。本轮本机 PG 18.4 用仅 SELECT/INSERT 的隔离角色验证 identity INSERT 成功、序列 USAGE 为 false，事务回滚后测试角色/对象不保留；这不是云 PG 17.11 实测。若后续改成 SERIAL 或直接调用序列，需要重新审查最小授权。

pg_catalog 内置函数及类型使用沿用 PostgreSQL 默认权限；若云端专门收紧内置函数 EXECUTE，需要核对现有查询与 advisory lock 所需函数，不扩大业务表授权。迁移账号负责建 schema/表及授权，业务账号不负责迁移。未来新表按实际 SQL 显式追加授权，不预授未来所有表的全权限。

依据：[PostgreSQL 17 Privileges](https://www.postgresql.org/docs/17/ddl-priv.html)、[GRANT](https://www.postgresql.org/docs/17/sql-grant.html)，结合当前项目 SQL。
