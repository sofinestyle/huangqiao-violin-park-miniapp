## 2. 推荐资源与域名分配（建议S，待确认D）

推荐在现有腾讯云账号下新建上海地域CloudBase PG模式Production环境，分别部署Node API、自研React Admin静态应用、私有媒体存储，并配置独立数据库角色、服务凭据及备份目标。小程序仍只访问Node API，不能直接连接PG或携带服务角色密钥。CloudBase支持按环境隔离资源；实际套餐、地域、网络及配额需按创建页面核实。[官方环境说明](https://docs.cloudbase.net/quick-start/create-env)

本轮未盘点账号是否另有已购、空闲且满足隔离条件的环境；实施前先清点，符合条件时评估复用，不能因为本方案就重复购买。现有Staging业务库及媒体空间不能作为这种复用目标。

| 对象 | Development | Staging保持 | Production候选 |
|---|---|---|---|
| API | 现有本机8787 | 当前CloudBase统一网关 | `api.yorray.com`，待DNS、备案接入、HTTPS及配额核实 |
| 后台 | 现有本机后台 | `admin.yorray.com` | 首发建议`admin-prod.yorray.com`，不改现有Staging入口 |
| 数据库 | 本机PG | 现有Staging PG | 新环境中的独立业务库/Schema及角色 |
| 业务媒体 | 本机Legacy媒体 | 现有Staging媒体 | Production专用私有存储及凭据；不复用Staging对象空间 |
| 固定UI图 | 当前包内资源 | 当前包内资源 | 首发沿用包内资源；满足真实包限制即可，不将CDN设为必购前提 |
| 会话与账号 | 本地身份 | Staging账号/会话 | 单独初始化后台账号；访客令牌按production独立存储 |

这些是名称建议，不是已存在的资源，尤其不能把api.yorray.com当作已可用地址填入代码。新环境ID、数据库名称及连接信息由真实资源生成，不编造。

**后台域名的另一方案：** 若公司要求正式后台必须使用`admin.yorray.com`，则先另行批准Staging迁往`admin-staging.yorray.com`，验证其同源路由、唯一ADMIN_ORIGIN和新登录，再按切换窗口把admin域名接到Production。Staging旧webapps/网关入口应继续进入Staging，不能因为正式域名复用误入Production。跨域Cookie不复制，账号需重新登录；DNS、证书、网关绑定及切换时长均须实测，不承诺无中断。本方案首发推荐不迁移现有Staging，以减少变更面；该选择由负责人决定。

Production后台仍须`/`及`/api/admin/`同源到正确服务，保留HttpOnly、Secure、SameSite=Strict、唯一HTTPS ADMIN_ORIGIN及X-HQ-Action。小程序API与后台可使用不同域名，但后台不能改成跨域fetch、放宽CORS或改写Origin绕过CSRF。

## 4. 数据与媒体初始化

Production先建立空的本项目业务Schema，执行已经验证并经批准的Migration；保留CloudBase系统Schema，不复制整库，不让应用启动时自动Seed。首次管理员通过一次性安全初始化建立，密码由负责人安全设置，不使用Staging密码副本。

| 可进入正式候选的数据 | 条件 |
|---|---|
| 首页/企业、乐器、文创、点位、研学套餐、教学和必要SKU | 负责人逐项确认名称、编码、价格/参考价、接待规则、联系方式、隐私及发布状态；不能靠批量改isTest=false变为正式资料 |
| 已获授权的业务图片/视频 | 核实权属及内容，进入Production专用私有媒体空间，重新建立media关联及`/api/media/<id>`引用，校验原件摘要/大小与关联完整性 |
| 固定UI资源 | 保留包内视觉资源及原件；不要把后台业务图片转为包内常量 |

初始内容可以由后台重新录入，或另行批准“正式内容白名单导入”：先Dry-run列出数量、冲突、媒体映射及差异，人工确认后再执行。白名单不得包括账号密码、旧认证数据、sessions、visitors、bookings、consultations、audit、idempotency、旧migrations历史或测试场次。Migration版本由新环境实际执行产生，不能导入旧历史充当初始化。

当前同名套餐或不同编码/年龄/时长版本应先决定正式采用项；此前保留的Development另一版本不能因“两个都保留”就自动成为正式发布内容。所有正式候选须重新扫描旧`/assets`、localhost、Development路径及Staging媒体引用。历史审计发现过旧URL，不代表今天数量未变；本轮未联网扫描业务内容，不能报告为0。

正式公开内容按正常业务维护、审核、发布；真实预约/咨询历史不从测试环境转入。完整写入闭环先在Staging或隔离验收库使用合成资料验证。Production匿名只读检查不写业务数据；若以后安排真实登录/试单，必须明确允许产生哪些会话、审计及业务记录，不能一边执行一边宣称零写入。

## 5. 微信平台、真机与媒体验收

实施时先核对正确AppID的主体、管理员/开发者/体验者权限、类目、图标/简介、隐私指引、服务说明、联系方式及审核材料。内容必须符合公司确认事实与实际采集字段，不能代填未经确认的资质、营业范围或隐私声明。

当前使用wx.request访问Node网关，继续核对微信request合法域名；涉及下载、视频及重定向的最终目标逐项核查。不能只配置admin后台域名，不能把CloudBase前端安全域名与微信服务器合法域名混为一项；本地不校验选项不替代平台配置。

体验验证须在域名/TLS校验开启的条件下完成：开发工具编译、官方包体积输出及至少实际iOS/Android微信设备。逐项打开首页、乐器、文创、研学、教学、点位导览、我的，以及品牌分包、产品详情、隐私页、业务图片和公开视频。检查首次分包下载、图片失败提示、视频播放/拖动/Range、弱网超时与GET实际重试；写请求不自动重试。页面可读不等于登录与预约闭环通过。

包体积必须取本次候选的官方编译/预览或上传检查，区分主包、分包、总包、质量优化建议与硬上限。已有包内优化图方案可以继续，不能把此前200K资源质量提示当作必须采购CDN的理由；也不能沿用旧包体积冒充新候选结果。微信官方页面本轮抓取未成功，具体审核界面、配额及当前包限制仍须在获准的平台操作中复核，不引用未打开的搜索摘要作当前规则证明。

提交审核的动作与正式发布分开：材料与候选验证完成后再次按负责人确定的范围执行上传/提审；审核通过只记录结果，暂不发布。不能由main推送自动触发微信发布。当前选择“本轮不上传”优先于先前提审意向。

## 6. 稳定性、费用与运维

建议API先以最小1、最大5及0.25CPU/0.5GiB作为容量评估起点，不承诺足够承载正式峰值；按实际负载测试、内存和数据库连接预算决定是否增加规格。最小1减少应用缩零冷启动，不等于高可用，也不证明数据库、DNS、网络或第三方接口不会超时。

共享PG成本较低但存在共享资源波动，独享PG的资源更可控；生产是否采用独享及实际可选规格需根据询价和业务可用性要求决定。不要把其他数据库的自动暂停功能或“14天回档”直接当作当前PG能力。[官方PG实例与计量说明](https://cloud.tencent.com/document/product/876/120713)

**费用测算，非下单报价或实扣账单：** 按上海公开牌价、30天720小时估算；标准版公开价199元/月、含33万资源点，可作为询价基线。资源点消耗先抵套餐，不能把套餐费与已抵扣用量重复相加；Production能否使用既有余额须单独核实。[官方价格](https://cloud.tencent.com/document/product/876/127357)

| 项目 | 计算示例 | 资源价值 |
|---|---|---:|
| Node常驻1实例 | `(0.25×0.055 + 0.5×0.032)×720` | 21.42元/30天 |
| 共享PG持续活跃 | `0.5×0.342×720` | 123.12元/30天 |
| 独享PG示例1核2GiB内存、20GB存储 | `1×0.342×720 + 20×0.0005×720` | 253.44元/30天 |

PG两行是互斥示例，规格可用性未核实；均未计媒体/备份/公网流量、额外实例和独立费用。保留Staging还会保留其费用；本轮未查新购买页、优惠资格或账单，不能承诺项目月费封顶199元。

共享PG公开规则按有使用的5分钟窗口计量；当前源码视频worker每15秒查询一次，即使没有游客也可能覆盖所有窗口，故123.12元是依源码持续正常运行作出的预算推算，不是Staging已实扣证明。健康探测、备份也会影响使用窗口。不能为省钱直接停用任务清理；若要改调度须另列改动并验证租约、幂等及失败清理。

普通API继续20秒，GET最多重试1次、总读预算40秒，写入不自动重试；上传沿用独立策略。监控健康、5xx、延迟、实例/内存、PG连接、媒体失败、任务积压、备份及预算，报警交给明确负责人；预算告警不等于硬停费上限。

连接预算应覆盖扩缩容和滚动发布：`连接池上限×同时存活实例数 + 管理/迁移/监控预留 < 数据库上限`。旧版5加新版5、每实例10连接时，仅应用就可能需100连接，这是容量假设示例，不是平台已保证的发布峰值。

60分钟及至少8小时隔夜的首访由人工安排，首次入口前不人为探测或预热；记录实际受控访问、设备休眠及后台任务/监控存在，不能宣称全局无其他流量。后台首开与小程序首开分别验证。现有闲置自动化继续暂停，不因本方案恢复。

## 7. 备份恢复与回退门槛

现有PG备份已支持数据库快照与媒体清单校验，但调度尚需落实。现有restoreData要求数据库所有非系统表为空，并将恢复媒体交给本地目录适配；CloudBase初始平台表可能使此前置检查失败，恢复到本地目录也不等于私有云媒体已恢复。因此须先完成“仅本项目空业务Schema、平台对象保留、正确云媒体目标”的隔离恢复演练，再宣称具备正式恢复能力。

保留原先数据库每3天、图片每周、备份30天的政策输入；建议正式业务提高至每日数据库及新增媒体备份，是否提高由负责人批准。备份加密并放独立故障域，视频亦纳入，清理仅针对过期备份集。恢复点目标和恢复耗时以联合演练实测，不能只备数据库就承诺所有图片/视频可恢复。

API及Admin回退到上一份已验证制品，前提是Schema向后兼容；回退代码不自动回退数据库、不删除真实预约和咨询。迁移失败优先隔离并向前修复或恢复到新目标核对。小程序回退能力按微信平台实际支持执行，不承诺像容器即时切换；服务端须兼容仍在使用的旧客户端。
