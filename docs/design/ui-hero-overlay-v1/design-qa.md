## 补查问题与修正迭代

正常态首轮同图及局部检查通过，但在保留旧首页内容的Loading／Error受控渲染中发现P2问题：背景上延55px会覆盖状态卡片下部，遮住重试按钮。`inspect-state-results.json`和`inspect-error-390.png`记录了重叠，补查时整体结果为blocked。

仅增加首页CSS同级选择器：读取提示或错误卡片存在时，图片层恢复在Hero内显示，避免跨过状态区域；正常态仍上延55px。没有调整TS、错误判断、条件分支或重试逻辑。重新原生编译后，两种状态均测得无重叠；实际点击“重新加载”后首页成功重新读取，error清空。`verify-state-results.json`及前后状态同图 `state-overlap-comparison-390.png`为修正后证据；最终正常首页也重新捕获。最终无本轮仍需修正的P0/P1/P2问题。

## 预期差异与限制

新背景从品牌栏背后开始，照片取景相应变化，不机械保持旧图每一像素的位置。微信原生标题栏与状态栏保持现状；图片起点指页面内品牌栏顶部。900字重在当前原生模拟器中确认更粗，真实iOS／Android字体回退未复测，不承诺各平台字形完全相同。

Loading／Error以及site缺失状态通过临时setData受控渲染检查，操作后恢复原数据；这不是实际断网或后台下架演练。未执行本轮320／375／430px、微信真机、辅助功能及真实弱网复测；未重做底部原生导航逐个点击及原生返回按钮补验。保留源码和此前通过记录不等于这些项目本轮通过。仅建议对当前390px截图及实际页面进行人工验收，不自动开始其他UI阶段。
