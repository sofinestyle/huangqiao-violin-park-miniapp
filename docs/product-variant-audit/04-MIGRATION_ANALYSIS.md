# 零丢失迁移与兼容分析（未实施）

本轮没有新增Migration、创建表、修改产品、运行seed或改写任何快照。以下是推荐B被人工确认后可进入DCR的候选设计，不是已经执行的迁移方案。

## 1. 迁移原则与映射

| 旧数据 | 可自动保留的目标 | 不能自动推断的部分 |
|---|---|---|
| content.id、code、name、共性字段、发布状态、版本 | 保持原产品身份和资料；保存切换时版本 | 不能顺带改产品编码/类别/正式资料状态 |
| specs[].name | legacy_name原文，赋稳定SKU ID | 不把“4/4棕色”自动拆成尺寸4/4、颜色棕色；空名/重名不能猜 |
| specs[].description | legacy_description原文 | 实际不是params；不自动把材料文字重分配到产品或Option |
| specs[].price | reference_price及原字段存在性记录 | 缺省、null、0分别保留；不自动填0/改币种/四舍五入 |
| specs[].images | 原URL、顺序及缺省状态 | 不复制媒体文件，不自动把相似图合并或按颜色猜图 |
| 原数组位置 | 首次迁移生成sort_order与溯源键 | 之后不能用新数组位置反推身份 |
| 规格未知键 | legacy_payload无损原件 | 服务端旧spec允许未知键，不能仅按已知四键搬迁后丢掉其它数据 |
| 旧咨询snapshot | 完全保留原始JSON | 不根据名称追填skuId，也不伪造当时价格/图片 |

当前28产品/56规格均为开发数据，数据量小，不代表可删除重置。建议自动“包裹为Legacy SKU”，人工建立维度并将旧SKU指向确认组合；结构映射与首次复制分开。当前尺寸名虽然易读，也必须由管理员确认其业务含义，不能升级为自动解析批准。

## 2. 迁移控制与验收门槛

1. 批准DCR后，备份SQLite和媒体并校验恢复到隔离位置，保存原产品完整JSON、hash、version及迁移映射清单；本轮未执行这些写操作。
2. 在隔离库dry-run逐产品产生差异报告：旧条数/新条数、ID映射、名字/说明/价格/图片顺序、未知键、无图、重名、缺价、超长、无效URL等。不能只按当前良好样本设计。
3. 映射键候选 `(product_id, source_version/hash, old_ordinal)`，首次生成稳定SKU UUID并持久记录；重跑使用已有映射。旧ordinal仅用于固定快照溯源，不是新系统身份。
4. 产品仍旧版本时才事务切换；发现有人编辑则停止该产品并重新审阅。写SKU、Options、modelVersion及审计必须原子完成；异常整事务回滚，不留半迁移产品。
5. 对比保存前后的所有原始字段及多重集合、顺序、媒体引用集合，核对来源hash；当前样本应保留56条原规格，不含为零规格产品新增的Default SKU（本库当前无零规格产品）。
6. 迁移不改历史咨询和历史审计；仅增加迁移操作记录/未来SKU变更摘要。不能用现audit的version回推旧规格内容。
7. 回退应优先使用切换前逐产品快照和版本门槛；新模型已有新写入时不可直接恢复整库覆盖，须冻结相关写入、导出差异并制定保留新记录的回退步骤。恢复过程先在隔离环境演练。

## 3. 推荐有限期混合读取、单一权威写入

不推荐一次上线就删除specs协议。即使现数据都是开发资料，微信客户端包/页面缓存仍可能暂时使用旧结构；Admin、媒体和咨询也是独立消费点。

建议按产品modelVersion区分v1/legacy与v2，短期双读但**不双份任意写**。v2产品由SKU模型生成旧 `specs[]` 投影，旧客户端可继续读名称/说明/价格/图库；没有独立价的旧条目仍保持缺省/空，而非强行补默认价导致多出价格行。产品主价与规格价展示差异须保留或另经批准。

旧Admin对已升级产品提交v1数组时，必须拒绝不安全写入并提示刷新/升级，或采用经过证明的显式适配；不能默默丢掉SKU或把整个矩阵重建。这是旧写客户端能力边界，不应伪称所有版本写入完全向后兼容。需在DCR明确切换窗口、客户端升级和旧写阻断行为。

旧咨询仍可携带spec名称：只有在当前产品内能够无歧义匹配有效SKU时适配；重名、改名、停用或旧页面过期时返回可恢复的刷新提示，不能猜ID。新咨询加skuId并校验归属和启用/发布状态；旧spec保留给旧读端，新快照可额外保存SKU ID/code、Option和值标签/ID及产品版本。历史快照不追填。

兼容退出条件：新旧协议契约测试通过；已知客户端升级覆盖满足约定；旧调用观测与弃用窗口达到DCR门槛；全部目标产品映射完成。不能编造已经不存在旧调用的证据。

## 4. 可能受影响的API（全部候选，未修改）

| Endpoint | 候选影响 | 兼容判断 |
|---|---|---|
| GET /api/public/content | 产品列表保持原结构，可增加modelVersion；仍产品级列表 | 新增字段可向后兼容；不要自动在列表加载无限SKU详情 |
| GET /api/public/content/:id | 增加options/skus并保留specs投影 | 读取兼容；字段/空值和价格图继承须契约测试 |
| GET /api/admin/content、/:id | 返回SKU编辑模型及legacy状态 | 新Admin适配；旧读端可保留投影 |
| POST /api/admin/content | 可接收结构化product payload，复用权限 | 扩展版本协议；旧产品创建可在过渡期保留 |
| PUT /api/admin/content/:id | 原子保存选项/SKU差分、保留version并发检查 | **不能自动认为旧写兼容**；已升级产品的旧payload须受控拒绝 |
| POST /api/visitor/consultations | 可选skuId；spec过渡兼容、增加归属/启停校验 | 参数增量；有歧义旧名称不能静默接受 |
| GET /api/visitor/consultations及/:id；GET /api/admin/consultations及/:id | 原snapshot.spec保留，新记录可增SKU快照字段 | 旧历史可读，不能强制历史记录必须有skuId |
| GET /api/admin/media | usedBy覆盖SKU，必要时增加SKU层详情 | 保留原内容级关系输出；新增信息不删除旧字段 |
| GET/HEAD /api/media/:id | 公共引用查询覆盖SKU，防未发布/停用图误公开 | URL兼容，授权语义需DCR及回归 |
| POST /api/admin/media；GET /api/admin/media/:id/file | 继续原上传及预览 | 预期无需协议变更，验证权限不扩大 |
| GET /api/admin/audit | 可展示未来SKU操作摘要，原分页/筛选保持 | 不修改历史action；若新增action需补中文映射 |
| GET /api/admin/export | 原预约/咨询CSV | 建议本SKU阶段不变，不能顺带新增导出字段 |

**新增Endpoint：MVP建议不必新增。** 矩阵生成可先在客户端预览、服务器保存时重新校验；现content保存承载原子变更。未来确有独立SKU查找/批处理需求再提出新Endpoint，避免为规范化机械增加API。本轮实际新增、修改Endpoint均为0。

## 5. 单规格及媒体特殊情况

简单模式底层一个Default SKU，旧零规格接口投影可保持 `specs:[]`；旧单规格4/4保留原展示标签及数据。legacy多规格在未人工映射前继续自由文本读取，不能强行套同一个Default SKU。

10SKU/2颜色图可先共用媒体URL加批量关联；新SKU表引用必须加入媒体usedBy和公开可见性计算。建议public仅考虑已发布产品可公开的SKU，但停用图是否继续可见、历史预览权限与缓存需要DCR，不让历史咨询获得未授权文件。删除/退役SKU不自动删除媒体。
