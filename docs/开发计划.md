## 目标与控制原则

按新版需求建立可运营的小程序与后台。首页原 HTML 保留作视觉参考，重新实现微信原生页面；不得直接以 H5 包装交付。公司负责业务规则、素材真实性、账号归属及内容发布审核；实施方负责能力验证、工程实现、测试证据与交付；接待和客服负责人负责业务处理与运营试用。具体人选待公司指定。

需求分为 C 已确认、R 原稿保留、S 补充建议、D 待确认。新版功能细节中的 S 可用于原型和隔离测试设计，生产规则与上线参数须另行确认。阶段按进入条件推进，当前信息不足以承诺固定天数或上线日期。

## 同期建设的工作包

游客端原计划按需求建议页面组 P01—P18组织；实际注册19个页面（含后续新增品牌介绍页），以app.json及当前功能说明为准。原计划范围：五个一级页面，以及产品详情、套餐详情、个人/家庭和团体申请、预约与咨询详情、教学、点位、联系和主体说明。教学从首页进入。内容不足的区块可暂不发布，必须记录原因，不能以虚构内容补齐。

后台覆盖工作台、首页和园区内容、提琴文创、研学套餐、场次预约、咨询、教学媒体、账号与审计。各业务模块同步形成后台维护和处理能力，不把后台延到游客端全部完成以后。

工程数据对象覆盖站点配置、产品与规格、套餐参考信息、场次、预约与变更、咨询、教学课程、点位、媒体、工作人员角色与日志。本地表结构及接口已实现，SQLite只用于隔离验证；正式数据库及未确认票型仍待选定。不预建支付订单、库存或财务台账。

## 决策门槛和风险

1. 技术选型门槛：真实保存与查询、多人权限、并发确认不超额、视频文件上传及下架、备份恢复与数据导出必须有实际证据。任何一项失败都需记录原因及替代方案，不能以平台营销说明替代。
2. 内容发布门槛：产品参数、品牌标志、联系方式、点位开放安排、视频授权及宣传统计经公司审核。套餐01存在原稿约130分钟与2小时冲突，需处理后才能对外承诺行程。
3. 运营门槛：指定接单责任人、联系时段、处理方式、现场登记人员和账号权限。软件保存申请不等于工作人员能及时接待；运营人工是持续成本。
4. 发布门槛：公司账号权限、类目、适用备案、隐私说明、域名和媒体策略经当时平台配置核对；云资源费用及续费责任明确。
