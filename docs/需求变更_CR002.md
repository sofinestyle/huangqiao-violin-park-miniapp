## 已确认要求

用户要求“研学栏目内增加研学报名选项”，由工作人员在后台场次管理发布已经成团的信息，游客可以跟团报名。用户进一步明确回复“提交申请，人工确认后占名额”和“登记系统外人数，计入总人数上限”。对应C13/C14与DEC014，不重复要求确认。

底部仍为首页、乐器、文创、研学、我的；既有个人/家庭预约、团体需求、咨询、人工变更及到访流程保留。乐器文创仍展示咨询、线下成交，没有新增下单和支付。

## 实现与操作

| 环节 | 本轮实现 | 关键规则 |
| --- | --- | --- |
| 后台场次管理 | 登记系统外已成团人数，显示系统已确认和剩余名额；同一表单维护活动名称、套餐、介绍、集合地点、公开费用/报名说明及发布状态 | 发布须填写必要资料并登记已有人员；人数上限由工作人员填写，不生成正式默认容量 |
| 小程序研学 | 新增研学报名入口、活动列表和详情，可按日期筛选、查看套餐及咨询 | 仅展示已发布、未暂停、日期未过且套餐仍发布的活动；满员可查看但不能申请 |
| 跟团申请 | 活动日期、时段、套餐自动固定，填写成人/儿童人数与联系方式，保存待确认申请 | 提交不锁定名额；服务端拒绝篡改活动参数与超过当前剩余人数的申请，重复提交同编号 |
| 人工确认 | 研学预约按跟团筛选，活动名称检索；详情显示报名时信息和原选场次 | 工作人员联系后确认，事务核对系统外人数与本系统已确认人数，再计入占用 |
| 历史与停止报名 | 活动及套餐信息随申请保存快照；发布、修改人数、确认等留下操作记录 | 下架或暂停停止新增报名，已有记录保留；有报名历史后不能直接改日期、时段或套餐 |
| 升级与恢复 | 数据库版本3增加活动配置和外部人数；旧场次原值保留且不自动公开 | 迁移只执行一次；备份恢复包含新增字段，恢复后旧会话失效 |

详细逐步操作见[本地操作说明](本地开发与操作说明.md)。后台内部接待说明不在公开场次或活动接口中返回；匿名游客不会看到人员名单、联系人、内部计数明细或工作人员身份。

## 补充实施建议及待确认边界

活动封面沿用管理员维护的套餐图片，避免重复上传。公开费用说明为空时提示联系工作人员，不形成应付金额。已有报名历史后保留原日期、时段和套餐，安排变化需另建场次或按已有人工变更流程处理。满员活动保留供查看；下架停止新增报名，已有待确认申请仍由工作人员联系决定，暂停则同时阻止新确认。以上是本轮实施建议，不替代公司的正式服务政策。

正式容量、实际成团标准、优惠与票型、报名截止时刻、材料/交通、共享工坊和导师资源、接单时效、取消改期规则仍按D01—D03/D07核定。发布校验“已有人员”不等于批准某个人数门槛；系统外人数必须如实维护，后续转入系统确认时避免重复计算。日期过滤尚不自动实施当天小时截止或未确认的提前期。
